# v0.8 Image Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.8: `Image` and the `radius.image` token (Spec 17).

**Architecture:** `Image` is a `"use client"` polymorphic component. A `span` frame (a `Box`) takes layout props, `className`, and `style`, and sets the ratio and corners. The `as` element (`img` by default, or `next/image`) gets `ref` and the remaining props. Load state lives in `Image`, which composes the project's `onLoad`/`onError` and checks `complete`/`naturalWidth` when the `img` mounts. `radius.image` is a new required alias token, and `Prose` uses it.

**Tech Stack:** As v0.7. There are no new dependencies. `next` stays a fixture-only dependency.

**Spec:** `docs/specs/17-image.md`, with `docs/specs/05-component-conventions.md`, `docs/specs/02-tokens-and-themes.md` (`radius.image`), `docs/specs/11-prose.md`, `docs/specs/13-data.md` (`Skeleton`), and `docs/specs/16-feedback-and-display.md` (`Avatar`'s image states). Read the task's spec section before starting it. Exact values live there, and this plan doesn't repeat the spec tables.

   - **Recommended: accept,** and amend Spec 04's line to add `image`, with `RadiusToken` in `src/components/Box/types.ts:128` to match. Cost: none for consumers. `<Box borderRadius="image">` becomes valid, which matches "every `radius` token".

   - **The owner accepted the recommendation (2026-11-13).**

## Review Focus

Each one has a test in the named task.

1. **An `Image` inside `Prose` (Task 3).** `Prose`'s `img { height: auto; border-radius: radius.image }` must not reach it. With `ratio`, the image fills the frame, and `radius="none"` stays square.
2. **A `src` that's already loaded when it mounts or changes (Task 2).** A cached image, or a `data:` URI, can be `complete` before React attaches `onLoad`. It must not stay in `data-loading` with its skeleton showing.
3. **A failed `src` replaced by a good one (Task 2).** `data-error` and the fallback go away, and `data-loading` returns until the new image loads.
4. **`onLoad` through `next/image` (Task 4).** `next/image` wraps `onLoad`. With `as={NextImage}`, `data-loading` must still clear after the image loads, in the real fixture.
5. **A decorative image that fails (Task 3).** With `alt=""`, the accessibility tree has no image, and nothing from the fallback.
