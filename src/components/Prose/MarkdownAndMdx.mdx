# Markdown and MDX

`Prose` styles plain HTML, so content written in JSX, compiled from MDX, or rendered from Markdown or a CMS needs no classes.

## Children

Write the content as elements inside `Prose`:

```tsx
<Prose as="article" marginX="auto">
  <h1>Writing a useful changelog</h1>
  <p>The hardest part is knowing what to leave out.</p>
</Prose>
```

## An HTML string

If your Markdown pipeline or CMS produces an HTML string, pass it to `Prose` itself, not to a wrapper inside it, so `Prose` can trim the first and last margins:

```tsx
<Prose as="article" marginX="auto" dangerouslySetInnerHTML={{ __html: html }} />
```

**`Prose` doesn't sanitize it.** Sanitize HTML you didn't write where you produce it, for example with a sanitizer step in your Markdown pipeline. MDX and children avoid HTML strings altogether.

## MDX: map elements to components

MDX can render library components for plain elements. Map `a` to `Link` to use your router, and `table` to `Table` (coming in a later release) for wide tables:

```tsx
import NextLink from 'next/link';
import { Link, Prose } from '@adeebali/design-system-react';

const components = {
  a: (props) => <Link as={NextLink} {...props} />,
};

<Prose as="article">
  <Content components={components} />
</Prose>;
```

Mapped components keep their own styles: a component's class beats `Prose`'s element rules.

In a Next.js server component, `next/link` is a server wrapper, which works with `Link` but can't be passed to a client component such as `NavBarLink`. For those, re-export it from a client module and import that instead:

```tsx
// app/next-link.tsx
'use client';
export { default } from 'next/link';
```

## Code blocks need a keyboard route

A `pre` that scrolls sideways must be reachable by keyboard, and not every browser makes a scrolling region focusable. `Prose` can't add `tabindex` to elements it's given, so add it where they're made. In MDX:

```tsx
const components = {
  pre: (props) => <pre tabIndex={0} {...props} />,
};
```

With a rehype plugin, set `node.properties.tabIndex = 0` on each `pre` element.

Syntax highlighters such as Shiki add their own colors inside `pre`. `Prose` supplies the block's font, background, and border.

## `NotProse`

Wrap anything `Prose` should leave alone, such as a `Card` in the middle of an article, in `NotProse`. It resets the font and color, and `Prose`'s element rules skip everything inside it.

```tsx
<Prose as="article">
  <h2>Results</h2>
  <NotProse>
    <Card>
      <Stat label="Readers" value="21.4k" />
    </Card>
  </NotProse>
  <p>
    Use{' '}
    <NotProse as="span">
      <Badge>New</Badge>
    </NotProse>{' '}
    inline.
  </p>
</Prose>
```

## Headings and a sticky `NavBar`

Headings have a scroll margin that clears a `sticky` `NavBar` at its default size, so anchor links don't land underneath it. With a taller header of your own, set `--ds-prose-scroll-margin` to how far it reaches down the page, plus some room:

```css
:root {
  --ds-prose-scroll-margin: 7rem;
}
```
