# Table

Styled, semantic table parts, which work in server components.

## Usage

Use `Table` and its parts to display rows of data, especially when the data comes from a server or you need to render on the server. For a table that manages sorting, pagination, selection, and loading and empty states itself, use [`DataTable`](?path=/docs/components-data-datatable--docs).

- The parts hold no state, so sorting, paging, and selection stay in your own state.
- Pass header text in normal case, since CSS does the uppercase.
- `stickyHeader` sticks to the wrapper, so give the table a height limit such as `maxHeight="screen"`. Only a one-row header sticks; a header with two or more rows scrolls with the table.
- A sticky first column has a fixed width (half of `size.dialog.sm`, 12rem in Soft), and its text wraps inside it, so a focused cell is never hidden under it. Don't set a width on its cells.
- When a first-column cell spans rows (`rowSpan`), mark the rows it covers with `spanned` on `TableRow`.
- Only one `TableSortHeader` should be sorted at a time. `onSort` needs a client component, and `href` works from a server one.

## Accessibility

- The parts render native table elements, so screen readers announce rows, columns, and headers.
- `TableSortHeader` sets `aria-sort` on its header cell.
- A scrollable table is focusable, so keyboard users can scroll it.
