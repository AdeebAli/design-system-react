# Dialog

A modal task that needs full attention, including a confirmation.

## Usage

Choose by what the user must do next: `Dialog` (this page) for a short, focused task or decision; [`Drawer`](?path=/docs/components-overlays-drawer--docs) for a longer task beside the page; [`Popover`](?path=/docs/components-overlays-popover--docs) for a small panel beside its trigger while the page stays usable; [`Menu`](?path=/docs/components-overlays-menu--docs) for a list of actions; [`Tooltip`](?path=/docs/components-overlays-tooltip--docs) for a short, visual-only hint. See [Patterns/Overlays](?path=/story/patterns-overlays--choosing-an-overlay).

- `DialogTrigger` takes one element that renders a `button`, such as `Button`.
- Name it with `DialogTitle` (or `aria-label` on `DialogContent`).
- `Escape` closes it, and so does clicking outside unless `closeOnOutsideClick` is `false`.
- Without a close button (`alert`, or `showClose={false}`), add a `DialogClose`.
- `alert` confirms something destructive and is static: changing it remounts the dialog.
- A `Dialog` opened from an open `Popover` sits underneath it, so close the popover first.
- It's a client component.

## Accessibility

- It's modal: focus is trapped, the page behind is inert, and scrolling is locked. Focus returns to the trigger on close.
- `DialogTitle` names it and `DialogDescription` describes it.
- `alert` gives it the `alertdialog` role.
