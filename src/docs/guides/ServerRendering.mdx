# Server rendering

The setups on this page are the ones `fixtures/next-app` runs: a Next.js App Router app that installs the packed package and is tested in a real browser. The code shown from it is its own source.

## Server and client components

Components with no state or browser APIs have no `"use client"`, so they render as server components: `Alert`, `Badge`, `Box`, `Breadcrumbs`, `Card`, `Center`, `Code`, `Container`, `Divider`, `EmptyState`, `Flex`, `Grid`, `Heading`, `Icon`, `Inline`, `Inset`, `Kbd`, `Link`, `Pagination`, `Prose`, `Skeleton`, `Spinner`, `Stack`, `Stat`, `Table`, `Text`, and `VisuallyHidden`.

The rest are client components, marked with `"use client"`, and can still be imported straight into a server page: Next renders them on the server and hydrates them. Pass them only serializable props from a server component. A callback, such as `DataTable`'s or `Pagination`'s `onPageChange`, needs a client parent: the fixture's `DataTable` lives in a `"use client"` module. `Pagination` with `getHref` renders links and works from a server page.

The fixture's home page is a server page that renders both kinds side by side.

## The root layout

## Router links

Pass a router link through `as`, such as `as={NextLink}` on `NavBarLink`, `SidebarLink`, or `Link`, as the fixture's navigation does. In a server component, `next/link` resolves to a server wrapper that can't be passed to a client component, so re-export it from a client module first:

## `Image` with `next/image`

Pass `next/image` as `as`, so Next keeps resizing and optimizing the image. Use `fill` and `sizes` with a `ratio`, or give Next the intrinsic size through `htmlWidth` and `htmlHeight`.
